# 账号池：服务、账号与路由边界

本次改进参考账号额度面板的交互方式，而不是把桌面客户端的实现直接搬进 Web 管理端。Web 管理端负责授权交互和展示，真正持有凭据、查询额度、选择上游账号的是 Go 服务。

已对照 `yetone/magpie` 固定提交 `c6bdc172a01e1eb8713c596e33e1ef703eb9b4ee` 的关键源码，具体依据与没有移植的部分见 [Magpie 源码对照](./magpie-architecture-comparison.md)。

## 账号管理

- **引擎**是协议适配器：Gemini Web、AI Studio、GPT、WorkBuddy、第三方 Key 等。
- **服务卡片**是展示分组：WorkBuddy 国服和国际服分别显示；第三方 Key 按归一化的上游地址分组。展示分组不代表新增一套独立的调度池。
- **账号**持有独立的启停、凭据、健康状态和实时额度。点击名称展开详情，检查账号是明确的按钮操作，不再点击整行就发起检查。
- Gemini Web / AI Studio 的标准引擎标识分别为 `geminiweb` / `aistudio`；旧 `a` / `b` 添加链接仍兼容。
- 数据库仍保留 `(engine, label)` 唯一约束。新增 WorkBuddy 账号遇到相同邮箱或名称时，按 `名称 (2)`、`名称 (3)` 自动编号，包括国服与国际服同名的情况；以插入时的约束结果重试，支持并发新增。不会按名称覆盖旧账号凭据或启停状态，也不把自动编号当作真实账号身份去重。其他新增入口保持原有重名拒绝规则，但返回明确提示而不是 SQLite 原始错误。

服务卡片折叠偏好只保存在当前浏览器，不写进服务端账号或凭据。

## 结构化额度

`AccountState.quota` 保留兼容文案；`quota_snapshot` 为可选的可计算快照：

- `read_at`、`error`、`stale` 说明数据是否可靠。
- `windows` 区分窗口名称、单位、上限、剩余值、重置时间、即将到期额度。
- `aside` 标记分项窗口。套餐积分和额外积分分别显示，不能与积分合计再相加。

首批接入 WorkBuddy。其他引擎保留其真实额度文案，不能从文案或百分比伪造绝对余额。第三方多个 API Key 可能共享钱包，因此没有计费主体标识前，不跨 Key 汇总余额。

额度汇总回归可在 Node 22.6+ 环境执行 `npm --prefix web run test:quota`，覆盖分项与总计不重复、不同单位不混加、未知/过期/停用账号不误计等情形。

服务汇总只计算**当前就绪且已启用**账号的有效快照，并标注数据覆盖账号数。超过 15 分钟、采样时间异常、取数失败和未知额度不计入汇总，不把未知当作零。即使采样不到 15 分钟，只要任一窗口的重置或积分到期时间已到（或时间格式无效），整份快照也只作历史展示：分项改变会影响总计，不能继续累加旧总计，也不能猜测重置后的新额度。服务端生成快照和浏览器判断汇总有效性均检查这个边界。停用账号仍可查看其历史快照。额度摘要只用于观测，不直接修改现有选号规则。

当前不提供消耗预测曲线、签到或估算 token 余额；这些需要独立的历史采样与上游能力支持。

## 登录状态机

WorkBuddy 使用服务端获取授权链接和轮询授权状态，不需要管理员浏览器监听 localhost 回调端口。

浏览器轮询必须串行执行：上一请求结束后再安排下一请求，关闭或切换发行版后丢弃旧请求结果；临时网络错误可以重试，到期后重新获取授权链接。

服务端将授权会话绑定到开始时的发行版和代理，同一会话的完成操作需要串行并返回相同账号结果。缺失或过期会话直接拒绝，不能回退默认发行版。授权会话目前仍驻留单个进程：重启后需要重新授权，多副本部署需要将同一流程固定到同一实例。

## 路由和测试

生产请求仍遵守模型归属与账号能力约束。WorkBuddy 内部已有“过滤不可用账号 → 匹配发行版模型权益 → 优先消耗最早过期积分 → 无到期信息时轮询”的策略。本次没有把不同上游的额度百分比混成全局分数，也不跨未知模型兜底。

管理台「路由顺序」页可以保存一条全局顺序：供应商之间、供应商内部账号之间都按列表先后尝试，当前账号（或当前供应商全部账号）失败后才走下一个。请求会先走顺序里最靠前、且声明了该模型的供应商与账号；同一供应商内部由该引擎按顺序逐个失败切换。没有保存顺序时保持各引擎原有的轮询 / 智能选号行为，新账号按创建顺序排在列表末尾。显式 `routing.engine_models` 点名的模型与多模态模型仍保持单一归属，不做跨供应商兜底。

供应商模型弹窗中的测试显式传入 `engine` 和可选的 `provider`：

- 指定引擎就只探测该引擎。
- 指定第三方上游地址就只使用该地址下的账号。
- 目标不可用时返回该目标的错误，不用其他供应商的同名模型制造“测试通过”。

WorkBuddy 卡片的“引擎模型”管理双发行版共享目录，探测可以使用该引擎内任一发行版的可用账号，并非单发行版探测。

模型的开放/下架仍是**裸模型 ID 的全局设置**，不是供应商独立设置；弹窗已明确说明。旧的全局模型检查入口保持原有行为。
